`gitleaks.toml` is the default rule file of [gitleaks](https://github.com/gitleaks/gitleaks), copied byte for byte. Veilcode embeds it at build time (`crates/veilcode-core/src/scan/detect/gitleaks.rs`) and never downloads rules at run time.

## Update procedure
1. Find the latest gitleaks release tag and the commit it points to (GitHub releases page or API). Record both in `docs/VERIFY_LOG.md` with the URLs.
2. Download `config/gitleaks.toml` and `LICENSE` from that commit's raw URL, outside the repo.
3. Compute the sha256 and record it, the size and the rule counts in `docs/VERIFY_LOG.md`.
4. Re-check the schema (rule keys, allowlist form) and `detect/detect.go` (secret group, entropy, keywords, allowlists) at the new commit against `gitleaks.rs`. Any change in semantics needs a DECISIONS entry.
5. Replace `gitleaks.toml`, update the table above and `THIRD_PARTY_NOTICES` (licence text verbatim).
6. Run the standard checks. S15 (compile rate) must still pass; record any new compile failures.
